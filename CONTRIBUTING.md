## 1. Bảng đối chiếu nhanh: Phải làm & Tuyệt đối không làm

| Hạng mục | PHẢI LÀM (Đúng chuẩn dự án) | TUYỆT ĐỐI KHÔNG LÀM (Gây lỗi hệ thống) |
| :--- | :--- | :--- |
| **Gói thư viện Java EE** | Dùng `import jakarta.servlet.*`, `jakarta.persistence.*`, `jakarta.validation.*` | Không dùng `import javax.servlet.*`, `javax.persistence.*`, `javax.validation.*` |
| **Thẻ JSTL trong JSP** | Dùng `<%@ taglib prefix="c" uri="jakarta.tags.core" %>` | Không dùng `uri="http://java.sun.com/jsp/jstl/core"` (chuẩn JSTL 1.2 cũ) |
| **Chống XSS trong JSP** | Bọc mọi dữ liệu động bằng `<c:out value="${bien}"/>` | Không in trực tiếp `${bien}` chưa thoát mã HTML ra ngoài thẻ |
| **Biểu mẫu `POST` (CSRF)** | Mọi `<form method="post">` phải có `<input type="hidden" name="${_csrf.parameterName}" value="${_csrf.token}"/>` | Không viết form `POST` thiếu CSRF token (Spring Security sẽ chặn lỗi `403 Forbidden`) |
| **Flyway Migration** | Tạo tệp mới theo thứ tự tăng dần (`V3__mo_ta.sql`, `V4__mo_ta.sql`) với cú pháp SQL chuẩn ANSI | **Không bao giờ sửa hoặc xóa** tệp migration đã commit (`V1__*.sql`, `V2__*.sql`) |
| **Cú pháp SQL tự tăng** | Dùng `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | Không dùng `BIGSERIAL` hoặc `SERIAL` trong tệp `V*__*.sql` (làm lỗi H2 khi chạy `./mvnw test`) |
| **Biến môi trường `.env`** | Sửa `.env` ở máy cá nhân; cập nhật bản mẫu không chứa mật khẩu vào `.env.example` | **Không bao giờ commit tệp `.env` hoặc `.env.prod`** hay viết cứng (hardcode) API key trong `.java` / `.yml` |
| **Cấu hình `application.yml`** | Luôn có giá trị mặc định sau dấu hai chấm: `${TEN_BIEN:gia_tri_mac_dinh}` | Không viết `${TEN_BIEN}` trần không có mặc định (sẽ làm sập `./mvnw test` trên GitHub Actions) |
| **Thư viện `pom.xml`** | Dùng các thư viện đã có sẵn trong `pom.xml` | Không tự ý thêm dependency mới vào `pom.xml` khi chưa thống nhất với `TV1` |
| **Truy vấn JPA Lazy** | Nạp đủ dữ liệu liên kết bên trong tầng `@Service` có `@Transactional` | Không gọi getter của quan hệ `@ManyToOne(fetch = LAZY)` / `@OneToMany` ngoài tầng Controller hoặc JSP (`open-in-view=false`) |

## 2. Quy tắc sử dụng AI để viết code không bị sai kiến trúc

AI (ChatGPT, Claude, Gemini, Cursor…) rất dễ sinh code theo thói quen cũ (Spring Boot 2, `javax.*`, Thymeleaf thay vì JSP, hoặc tự bịa ra class chưa tồn tại). Hãy tuân thủ 3 bước sau:

### Bước 1: Cung cấp ngữ cảnh trước khi yêu cầu AI viết code

Đừng bao giờ hỏi câu chung chung như *"Viết cho tôi chức năng giỏ hàng"*. Hãy đính kèm cho AI:
1. Tệp Entity / Repository / Service hiện có liên quan tới tính năng đó.
2. Cấu trúc bảng SQL trong `src/main/resources/db/migration/`.
3. Đoạn mẫu prompt khóa kiến trúc ở Bước 2 bên dưới.

### Bước 2: Dùng mẫu Prompt khóa kiến trúc (Copy & Paste cho AI)

Mỗi khi mở cuộc trò chuyện mới với AI, hãy dán đoạn khung này ở đầu tin nhắn:

```text
Bạn đang viết code cho dự án TechCommerce với ngăn xếp công nghệ cố định sau:
- Java 17/21, Spring Boot 3.3.5 (packaging WAR), Jakarta EE 10 (BẮT BUỘC dùng jakarta.*, tuyệt đối không dùng javax.*).
- Giao diện: JSP + Jakarta JSTL 3.0 (uri="jakarta.tags.core") + SiteMesh 3.2.2 + Bootstrap 5.3.3.
- View Resolver đã có prefix="/WEB-INF/jsp/" và suffix=".jsp" (Controller trả về "catalog/list" sẽ trỏ tới src/main/webapp/WEB-INF/jsp/catalog/list.jsp).
- SiteMesh tự động bọc layout web.jsp (cho trang khách), auth.jsp (cho /auth/**), admin.jsp (cho /admin/** và /staff/**). Các trang JSP con chỉ viết nội dung bên trong <body>, KHÔNG lặp lại thanh navbar hay footer.
- Spring Security 6 đang bật CSRF: mọi form POST trong JSP phải có <input type="hidden" name="${_csrf.parameterName}" value="${_csrf.token}"/>.
- spring.jpa.open-in-view=false: mọi truy cập trường LAZY của Entity phải được xử lý xong trong @Service (@Transactional) trước khi trả ra Controller/JSP.
- Database: PostgreSQL 17 trên Production và H2 (MODE=PostgreSQL) khi chạy test. Nếu cần tạo bảng/cột mới, phải viết file Flyway migration mới (V3__..., V4__...) dùng cú pháp tương thích cả PostgreSQL lẫn H2 (dùng BIGINT GENERATED BY DEFAULT AS IDENTITY thay cho BIGSERIAL). Không bao giờ sửa V1 hoặc V2.
- Giao diện tối giản: chỉ hiển thị đúng dữ liệu và nút thao tác người dùng cần, không thêm các đoạn chữ quảng cáo hay thông số kỹ thuật dư thừa lên màn hình.
- Không thêm thư viện mới vào pom.xml.
```

### Bước 3: Kiểm tra code AI trả về trước khi commit

Sau khi áp code của AI vào dự án:
1. Kiểm tra phần `import` ở đầu file Java xem có dòng `javax.*` nào lọt vào không.
2. Kiểm tra file JSP xem có thiếu dòng `<%@ page contentType="text/html;charset=UTF-8" language="java" %>` ở dòng số 1 không (nếu thiếu sẽ bị lỗi font tiếng Việt).
3. Chạy ngay `./mvnw test` trên máy. Nếu có bất kỳ test nào đỏ, phải sửa ngay trước khi commit.

## 3. 6 Ràng buộc kỹ thuật bắt buộc (Làm sai là sập Build / Production)

### 3.1. Jakarta EE 10 (`jakarta.*`) và JSTL 3.0

Spring Boot 3.3.5 chạy trên chuẩn Jakarta EE 10:

```java
// SAI (Spring Boot 2 cũ — không biên dịch được)
import javax.servlet.http.HttpServletRequest;
import javax.persistence.Entity;
import javax.validation.constraints.NotBlank;

// ĐÚNG (Spring Boot 3.3.5)
import jakarta.servlet.http.HttpServletRequest;
import jakarta.persistence.Entity;
import jakarta.validation.constraints.NotBlank;
```

Ở đầu mọi file `.jsp`:

```jsp
<%-- SAI --%>
<%@ taglib prefix="c" uri="http://java.sun.com/jsp/jstl/core" %>

<%-- ĐÚNG --%>
<%@ page contentType="text/html;charset=UTF-8" language="java" %>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
```

### 3.2. Quy tắc Flyway Database Migration (`src/main/resources/db/migration/`)

Flyway tính mã băm (checksum) cho từng tệp SQL đã chạy trên cơ sở dữ liệu Production (Supabase PostgreSQL).

1. **Bất biến**: Các tệp `V1__init_stores_and_users.sql` và `V2__add_email_verification_otps.sql` đã chạy trên Production. **Tuyệt đối không sửa dù chỉ 1 dấu cách hay 1 dòng comment** trong các tệp này. Nếu sửa, container trên Production sẽ báo lỗi `FlywayValidateException: Migration checksum mismatch` và sập ngay khi khởi động.
2. **Cách thêm bảng hoặc thêm cột mới**: Tạo tệp mới theo số thứ tự tiếp theo, chú ý có **2 dấu gạch dưới (`__`)** sau số phiên bản:
   - `V3__add_catalog_and_inventory.sql`
   - `V4__add_cart_and_orders.sql`
3. **Tương thích đồng thời với H2 (Test) và PostgreSQL 17 (Prod)**:
   Khi chạy `./mvnw test`, toàn bộ các tệp `V1`, `V2`, `V3`... được chạy thật trên H2 in-memory (`MODE=PostgreSQL`). Do đó trong tệp migration:

   | Không dùng trong `V*__*.sql` (H2 báo lỗi) | Dùng thay thế (Chạy tốt trên cả PostgreSQL 17 và H2) |
   | :--- | :--- |
   | `id BIGSERIAL PRIMARY KEY` | `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
   | `JSONB` (nếu H2 bản cũ không nhận) | Dùng `TEXT` hoặc kiểm tra `./mvnw test` ngay sau khi viết |
   | `CREATE EXTENSION IF NOT EXISTS unaccent;` | Chỉ chạy lệnh PostgreSQL-only qua khối điều kiện hoặc xử lý chuẩn hóa chuỗi không dấu trong Java (`Normalizer.normalize`) |

### 3.3. Quy tắc SiteMesh 3.2.2, Form POST (CSRF) và Chống XSS

- **Không lặp lại Header / Footer trong trang con**:
  SiteMesh ([`SiteMeshConfig.java`](./src/main/java/com/techcommerce/config/SiteMeshConfig.java)) tự động lấy nội dung trong `<body>...</body>` của file JSP con để ghép vào khung [`web.jsp`](./src/main/webapp/WEB-INF/decorators/web.jsp), [`auth.jsp`](./src/main/webapp/WEB-INF/decorators/auth.jsp) hoặc [`admin.jsp`](./src/main/webapp/WEB-INF/decorators/admin.jsp).
  - Đường dẫn `/api/**`, `/ws/**`, `/assets/**` đã được loại trừ khỏi SiteMesh để trả JSON/tài nguyên nguyên bản.
- **Mọi biểu mẫu `POST` phải có CSRF hidden input**:
  ```jsp
  <form action="${pageContext.request.contextPath}/cart/add" method="post">
      <c:if test="${not empty _csrf}">
          <input type="hidden" name="${_csrf.parameterName}" value="${_csrf.token}"/>
      </c:if>
      <!-- các ô input khác -->
      <button type="submit" class="btn btn-primary">Thêm vào giỏ</button>
  </form>
  ```
- **Gửi AJAX / Fetch `POST` từ JavaScript**:
  Trong `<head>` của `web.jsp` và `admin.jsp` đã nhúng sẵn 2 thẻ `<meta name="_csrf">` và `<meta name="_csrf_header">`. Khi gọi `fetch()`, đọc token từ 2 thẻ này và đính vào header.

### 3.4. Lưu ý `spring.jpa.open-in-view=false`

Dự án tắt `open-in-view` để tránh giữ kết nối DB trong lúc render JSP (gây cạn kiệt HikariCP connection pool trên Supabase).
- Nếu một Entity có quan hệ `LAZY` (ví dụ `Product` -> `Category` hoặc `Order` -> `OrderItems`), **không được** chờ ra tới trang JSP mới gọi `${product.category.name}`.
- Hãy nạp sẵn trong phương thức `@Transactional(readOnly = true)` ở tầng `@Service` (dùng `JOIN FETCH` trong `@Query` hoặc chuyển sang DTO/ViewModel) trước khi đưa vào `Model`.

### 3.5. Sử dụng lại các thành phần dùng chung đã có sẵn

Trước khi viết class mới, kiểm tra xem dự án đã có sẵn chưa:
- **Thông tin người dùng & chi nhánh hiện tại trong mọi JSP**: [`CurrentUserAdvice.java`](./src/main/java/com/techcommerce/auth/CurrentUserAdvice.java) đã tự động bơm 3 biến vào mọi trang JSP:
  - `${currentUser}` (`UserPrincipal` của người đang đăng nhập, hoặc `null` nếu là khách)
  - `${currentStore}` (`Store` tương ứng với cookie `SELECTED_STORE_ID`, hoặc `null` nếu đang xem Toàn hệ thống)
  - `${activeStores}` (`List<Store>` gồm các chi nhánh đang hoạt động)
- **Đọc cookie chi nhánh trong Controller/Service**: Dùng `JwtService.readCookie(request, "SELECTED_STORE_ID")`.
- **Gửi email HTML chuyên nghiệp**: Dùng [`EmailTemplate.java`](./src/main/java/com/techcommerce/common/mail/EmailTemplate.java) và [`EmailService.java`](./src/main/java/com/techcommerce/common/mail/EmailService.java) (đã dựng sẵn khung HTML chuẩn: `EmailTemplate.wrap(...)`, `EmailTemplate.button(...)`, `EmailTemplate.infoTable(...)`, `EmailTemplate.otpBlock(...)`). Không gửi email dạng plain-text thô.
- **Sự kiện liên phân hệ**: Dùng [`DomainEvents.java`](./src/main/java/com/techcommerce/common/event/DomainEvents.java) và [`GuestCartMerger.java`](./src/main/java/com/techcommerce/common/cart/GuestCartMerger.java).

## 4. Quy trình sử dụng và cập nhật biến môi trường (`.env`)

### 4.1. Cơ chế nạp biến môi trường của dự án

Trong [`src/main/resources/application.yml`](./src/main/resources/application.yml), dòng cấu hình:

```yaml
spring:
  config:
    import: optional:file:.env[.properties]
```

giúp Spring Boot tự động đọc tệp `.env` ở thư mục gốc của dự án khi bạn chạy trên máy cá nhân (`./mvnw spring-boot:run`), mà không cần cài thêm thư viện ngoài.

### 4.2. Quy tắc bảo mật tuyệt đối với tệp `.env`

1. **Tệp `.env` chỉ nằm trên máy cá nhân của bạn** (đã được chặn trong `.gitignore`).
2. **Tuyệt đối không gỡ `.env` khỏi `.gitignore`** và không commit mật khẩu thật (DB password, Gmail App Password, Google Client Secret, Cloudinary API Secret, Cloudflare Tunnel Token) lên GitHub.
3. Nếu lỡ commit nhầm mật khẩu thật lên Git: phải **đổi/thu hồi (revoke) mật khẩu đó ngay lập tức** trên trang quản trị dịch vụ (Supabase, Google Cloud, Cloudinary, Gmail) vì lịch sử Git vẫn lưu lại kể cả khi xóa file ở commit sau.

### 4.3. Quy trình 5 bước bắt buộc khi muốn THÊM hoặc SỬA một biến môi trường

Khi tính năng của bạn cần thêm một biến môi trường mới (ví dụ thêm `VNPAY_API_URL` hoặc `CLOUDINARY_FOLDER`), bạn **không được chỉ thêm vào tệp `.env` trên máy mình** (vì máy của 3 bạn còn lại, GitHub Actions CI và máy chủ Production sẽ bị thiếu biến đó).

Hãy thực hiện đúng **5 bước** sau:

#### Bước 1: Thêm vào tệp `.env` trên máy cá nhân của bạn
Điền giá trị thật để bạn chạy thử trên máy:
```dotenv
CLOUDINARY_FOLDER=techcommerce_products
```

#### Bước 2: Cập nhật tệp mẫu [`.env.example`](./.env.example) (Có commit lên Git)
Thêm tên biến kèm giá trị mẫu hoặc để trống (không chứa khóa bí mật thật) và ghi chú rõ ràng để các thành viên khác biết cần bổ sung vào `.env` của họ:
```dotenv
# Thư mục lưu ảnh trên Cloudinary
CLOUDINARY_FOLDER=techcommerce_dev
```

#### Bước 3: Khai báo trong [`src/main/resources/application.yml`](./src/main/resources/application.yml) KÈM GIÁ TRỊ MẶC ĐỊNH
**Quy tắc sống còn**: Luôn đặt dấu `:` kèm giá trị mặc định an toàn `${TEN_BIEN:gia_tri_mac_dinh}` hoặc `${TEN_BIEN:}` (mặc định chuỗi rỗng).
```yaml
# ĐÚNG — có dấu hai chấm mặc định, khi chạy ./mvnw test không cần file .env vẫn khởi động được Spring Context
app:
  cloudinary:
    folder: ${CLOUDINARY_FOLDER:techcommerce_default}

# SAI — thiếu dấu hai chấm mặc định, GitHub Actions chạy test sẽ sập vì lỗi PlaceholderResolutionException!
app:
  cloudinary:
    folder: ${CLOUDINARY_FOLDER}
```

#### Bước 4: Kiểm tra với môi trường Test ([`src/test/resources/application-test.yml`](./src/test/resources/application-test.yml))
Chạy thử `./mvnw test`. Nếu тест cần một giá trị giả định riêng (như khóa bí mật đủ độ dài cho thuật toán băm), hãy khai báo giá trị giả định đó trong `src/test/resources/application-test.yml`.

#### Bước 5: Cập nhật cho Production (Nếu biến đó cần dùng trên `https://techcommerce.store`)
Nếu biến mới cần có mặt trên máy chủ Production:
1. Mở [`docker-compose.prod.yml`](./docker-compose.prod.yml), thêm biến đó vào mục `environment:` của service `app`.
2. Mở [`.github/workflows/cd.yml`](./.github/workflows/cd.yml), thêm dòng `"TEN_BIEN=${{ secrets.TEN_BIEN }}"` vào bước `Generate .env.prod from GitHub Secrets`.
3. Báo cho **`TV1` (Tech Lead)** để thêm giá trị thực của `TEN_BIEN` vào mục **Settings → Secrets and variables → Actions → Repository secrets** trên GitHub.

## 5. Nguyên tắc thiết kế giao diện JSP tối giản

Toàn bộ giao diện tuân theo hệ thống token trong [`src/main/webapp/assets/css/main.css`](./src/main/webapp/assets/css/main.css):
1. **Tối giản thông tin trên màn hình**:
   - Chỉ hiển thị dữ liệu và nút bấm mà người dùng thực sự cần để thao tác.
   - Không hiển thị các thông tin kỹ thuật nội bộ (như tên cơ sở dữ liệu `PostgreSQL`, cơ chế `JWT HttpOnly Cookie`, `Refresh Token`, phiên bản hệ thống) lên giao diện của khách hàng hay trang quản trị.
   - Không thêm các khối văn bản quảng cáo dài dòng, huy hiệu trang trí rườm rà hoặc các nút bấm giả chưa có chức năng.
2. **Dùng lại các lớp CSS của dự án**:
   - Khung thẻ nội dung: `.tc-card`, `.tc-card-header`, `.tc-card-selected`, `.tc-surface-subtle`.
   - Huy hiệu trạng thái: `.tc-badge` kết hợp `.tc-badge-primary`, `.tc-badge-success`, `.tc-badge-warning`, `.tc-badge-danger`, `.tc-badge-neutral`.
   - Mã đơn hàng, mã chi nhánh (`HN-01`), giá tiền, số lượng, số điện thoại: gắn lớp `.tc-mono` hoặc `.tc-tabular` để các chữ số thẳng hàng.

## 6. Quy trình Git, Chạy Test và Checklist trước khi mở Pull Request

### Quy trình làm việc trên nhánh

```bash
# 1. Luôn lấy code mới nhất từ nhánh develop
git checkout develop
```

### Checklist bắt buộc trước khi mở Pull Request

- [ ] `./mvnw test` báo **`BUILD SUCCESS`** (toàn bộ test hiện có đều xanh).
- [ ] Không có tệp `.env`, `.env.prod`, thư mục `.m2/` hay file `.bat` tạm nào bị đưa vào commit.
- [ ] Nếu có thêm biến môi trường mới: đã cập nhật `.env.example` và đã thêm giá trị mặc định `${BIEN:mac_dinh}` trong `application.yml`.
- [ ] Không sửa nội dung các tệp Flyway migration cũ (`V1__*.sql`, `V2__*.sql`).
- [ ] Không có dòng `import javax.*` nào trong code Java.
- [ ] Mọi file `.jsp` mới đều có `<%@ page contentType="text/html;charset=UTF-8" language="java" %>` ở dòng đầu tiên và mọi form `POST` đều có CSRF token.
