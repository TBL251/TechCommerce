# Nguyên tắc dùng AI để viết code trong dự án TechCommerce

Tài liệu này dành cho thành viên nhóm sử dụng AI (ChatGPT, Gemini, Copilot, Cursor…) để hỗ trợ viết code cho dự án. Mục đích không phải cấm dùng AI — mà là dùng đúng cách để không làm hỏng những gì đang chạy.

---

## Trước khi yêu cầu AI viết code

### 1. Cho AI đọc context trước

AI không biết dự án của bạn. Trước khi hỏi, cung cấp:

- File cần sửa (paste nội dung đầy đủ)
- File liên quan (entity, repository, controller, JSP tương ứng)
- Thông báo lỗi chính xác (stack trace đầy đủ, không tóm tắt)
- Mô tả rõ hành vi mong muốn

Nếu chỉ hỏi "sửa lỗi này cho tôi" kèm một dòng lỗi mà không có context, AI sẽ đoán và thường đoán sai.

### 2. Hỏi đúng phạm vi

Chỉ yêu cầu AI làm đúng thứ bạn cần. Ví dụ:

| Thay vì hỏi | Hỏi cụ thể hơn |
|---|---|
| "Viết trang giỏ hàng cho tôi" | "Viết `CartController.java` nhận `POST /cart/add` với param `productId` và `quantity`, đọc `cartId` từ cookie, thêm vào bảng `cart_items` đã có sẵn" |
| "Sửa lỗi đăng nhập" | "Lỗi `NullPointerException` tại `JwtAuthenticationFilter.java:52` khi cookie `access_token` rỗng — đây là code hiện tại: [paste]" |

## Khi nhận code từ AI

### 3. Đọc trước khi paste

Đọc lướt toàn bộ code AI trả về. Kiểm tra:

- Có import thêm thư viện nào không có trong `pom.xml` không?
- Có tạo class mới chưa tồn tại không (entity, service, repository)?
- Có thay đổi schema DB không (thêm cột, đổi kiểu)?
- Logic có phù hợp với cách project đang xử lý không?

Nếu AI thêm `@Transactional`, `@CacheEvict`, `@Async` hay annotation bất thường — hiểu lý do trước khi giữ lại.

### 4. Không để AI tự thêm dependency

Nếu AI đề nghị thêm vào `pom.xml`, hỏi nhóm trước. Mỗi thư viện mới là một rủi ro:
- Conflict phiên bản
- Tăng thời gian build
- Lỗ hổng bảo mật

Stack đã cố định: **Spring Boot 3.3.5, SiteMesh 3.2.2, JJWT 0.12.6, Cloudinary 1.39.0, Bootstrap 5.3**. Không thêm nếu chưa thống nhất với TV1.

### 5. Không để AI sửa file migration Flyway

File `V1__*.sql`, `V2__*.sql`... là **bất biến** sau khi đã chạy trên DB production. Nếu AI đề nghị sửa nội dung file migration cũ — từ chối. Yêu cầu AI viết file `V3__*.sql` mới thay thế.

Sửa migration cũ sẽ làm Flyway báo lỗi checksum trên production và toàn bộ ứng dụng không khởi động được.

## Sau khi áp code

### 6. Chạy test ngay

```bash
./mvnw test
```

26 test phải xanh. Nếu đỏ, không tiếp tục — debug lỗi hoặc rollback code AI vừa áp.

### 7. Không commit khi test đỏ

Dù AI bảo "code đúng rồi" — test đỏ là code chưa đúng. Không có ngoại lệ.

### 8. Kiểm tra thủ công luồng liên quan

Test tự động không bao hết UI. Sau khi áp code từ AI, mở trình duyệt kiểm tra ít nhất:
- Trang vừa sửa có load không?
- Hành động chính (submit form, click button) có chạy đúng không?
- Trang liên quan (trang cha, trang redirect đến) có vỡ không?

## Các lỗi thường gặp khi dùng AI

### AI viết code cho Spring Boot 2 / Jakarta EE cũ

Project dùng **Spring Boot 3** với `jakarta.*` package. Nếu AI viết `import javax.servlet.*`, `import javax.persistence.*` — sai. Phải là `jakarta.servlet.*`, `jakarta.persistence.*`.

Nói rõ với AI: *"Dự án dùng Spring Boot 3.3.5, Jakarta EE 10, không phải javax"*.

### AI tạo endpoint trùng hoặc conflicting

Trước khi để AI viết controller mới, tìm kiếm endpoint đó đã tồn tại chưa:

```bash
grep -r "RequestMapping\|GetMapping\|PostMapping" src/main/java --include="*.java" | grep "/duong-dan-can-kiem"
```

### AI đặt sai tên file JSP hoặc sai đường dẫn view

Convention của project: view resolver trỏ về `WEB-INF/jsp/`. Controller trả về `"auth/login"` tương ứng file `src/main/webapp/WEB-INF/jsp/auth/login.jsp`. AI hay bỏ sót `WEB-INF/jsp/` prefix.

### AI bỏ CSRF token trong form POST

Mọi form POST trong JSP phải có:

```jsp
<input type="hidden" name="${_csrf.parameterName}" value="${_csrf.token}"/>
```

hoặc dùng thẻ `<form:form>` của Spring. Nếu thiếu, Spring Security trả 403 Forbidden.

### AI viết Flyway SQL dùng cú pháp PostgreSQL-only

H2 (dùng trong test) không hỗ trợ `BIGSERIAL`, `ON CONFLICT DO NOTHING`, `gen_random_uuid()`. Dùng cú pháp ANSI tương thích:
- `BIGSERIAL` → `BIGINT GENERATED BY DEFAULT AS IDENTITY`
- `gen_random_uuid()` → không dùng trong migration, tạo UUID trong Java
- `ON CONFLICT` → không dùng trong V* migration

## Checklist trước khi mở Pull Request

- [ ] `./mvnw test` xanh (26/26)
- [ ] Không có file migration cũ bị sửa
- [ ] Không có dependency mới trong `pom.xml` chưa được thống nhất
- [ ] Không có `import javax.*` (phải là `jakarta.*`)
- [ ] Mọi form POST có CSRF token
- [ ] Đã test thủ công luồng liên quan trên trình duyệt
- [ ] Commit message theo Conventional Commits, tiếng Việt

## Giao tiếp với AI hiệu quả hơn

Mẫu prompt tốt khi hỏi về dự án này:

```
Dự án: Spring Boot 3.3.5, Jakarta EE 10, JSP/JSTL 3.0, SiteMesh 3.2.2,
Spring Security 6, JWT HttpOnly cookie, Spring Data JPA, PostgreSQL 17,
Flyway migration, H2 cho test.

[Paste file hoặc đoạn code liên quan]

Yêu cầu: [mô tả cụ thể cần làm gì]

Lưu ý:
- Không thêm dependency mới vào pom.xml
- Dùng jakarta.* không phải javax.*
- Nếu cần thêm cột DB, viết Flyway migration mới (V3, V4...) thay vì sửa file cũ
- Form POST phải có CSRF token
```

Càng cụ thể, AI càng ít đoán, code trả về càng ít lỗi.
